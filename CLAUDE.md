# CLAUDE.md

Основные инструкции для разработки проекта. Действуют для всех этапов.

## 1. Цель проекта

Браузерный редактор и симулятор цифровых логических схем — аналог Logic.ly.
Пользователь добавляет логические элементы на рабочее поле, соединяет их проводами
и в реальном времени видит, как меняются сигналы 0/1.

Функции: рабочее поле с перемещением и масштабированием, библиотека элементов,
drag-and-drop на поле, соединение проводами, логическая симуляция, отображение
состояний 0/1, автоматический пересчёт, удаление/перемещение/редактирование элементов,
сохранение и загрузка схем, генерация таблиц истинности.

Реализованные элементы: `INPUT`, `OUTPUT`, `CLOCK`, `AND`, `OR`, `NOT`, `BUFFER`, `NAND`, `NOR`,
`XOR`, `XNOR`, `MUX` (2:1, 4:1, 8:1), `DEMUX` (1:2, 1:4, 1:8), `D LATCH`, `D FLIP-FLOP`,
`T FLIP-FLOP`, `JK FLIP-FLOP`. Пошаговая симуляция (Start / Pause / Step / Reset) реализована.

Запланированы (архитектура не должна им мешать): `HALF ADDER`, `FULL ADDER`, `SR LATCH` как элемент
(сейчас собирается из NOR / NAND), DECODER / ENCODER.

## 3. Архитектура

Четыре слоя, зависимости направлены только сверху вниз:

```
UI (features/, components/ui)   — панели, тулбар, диалоги
Editor (editor/)                — слой React Flow: холст, узлы, провода, DnD
State (store/)                  — Zustand: схема, сигналы, состояние UI, управление симуляцией
Core (core/)                    — чистый TypeScript: логика, элементы, схема, движок, анализ
```

`core/` не импортирует React, React Flow и Zustand. Движок работает с доменной моделью
(`Circuit`), а не с объектами React Flow.

### Ключевые принципы

- **Схема и сигналы хранятся раздельно.** `circuitStore` содержит то, что сохраняется в файл.
  `simulationStore` содержит вычисляемые значения. Узлы и провода подписываются только
  на значения своих пинов.
- **Перемещение элементов не запускает симуляцию.** Перекомпиляция netlist выполняется
  только при изменении `structureVersion`: добавлении или удалении элемента или провода,
  изменении числа пинов. Изменение свойств без смены пинов (например, переключение `INPUT`)
  вызывает `engine.setProps()` и инкрементальный пересчёт.
- **При перекомпиляции состояние сохраняется**: `engine.exportState()` передаётся новому
  движку, поэтому защёлки и триггеры не сбрасываются при правке соседней части схемы.
- **Операции над схемой — чистые функции** из `core/circuit/`. Они возвращают новый `Circuit`.
  Store вызывает их, а не реализует правила сам. Id генерируются снаружи и передаются параметром.

### Элементы и расширяемость

Новый элемент — это файл с `ElementDefinition` и регистрация в `core/elements/index.ts`.
Палитра, движок, инспектор и сериализация работают через реестр, в них нет `switch` по типам.

`ElementDefinition` описывает:

- `type`, `label` (международное название: AND, MUX, D FLIP-FLOP), `description` (на русском), `category`;
- `defaultProps` и `propSchema` (редактируемые свойства для инспектора);
- `pins(props)` — входы и выходы с id, подписью и стороной (`side`). Число пинов может
  зависеть от свойств, например у n-входовых вентилей или MUX;
- `evaluate({ inputs, props, state }) → { outputs, state? }` — чистая функция. Новое состояние
  возвращается в результате, а не мутируется;
- `initialState(props)` — начальное внутреннее состояние (защёлки, триггеры, CLOCK). Элемент
  с `initialState` движок считает **элементом с состоянием**: его выходы публикуются на границе
  дельта-цикла (см. «Симуляция»);
- `unknownState(props)` — состояние с неизвестным содержимым памяти (Q = X) для таблицы истинности.
  Выходы из него не определённее выходов из любого достижимого состояния (контрактный тест);
- `onTick({ props, state, time }) → state` — реакция на шаг времени (CLOCK);
- `PinSpec.clock` — тактовый (динамический) вход: символ отмечает его значком ▷;
- `port` — роль внешнего вывода схемы: `{ kind: 'input', prop }` (значение задаёт логическое
  свойство, INPUT: `prop: 'value'`) или `{ kind: 'output' }` (значение — сигнал на первом входе,
  OUTPUT). Анализ (таблица истинности) находит входы и выходы по роли, а не по типу.
  Контрактный тест проверяет согласованность роли с пинами и `evaluate`.

Как элементы ложатся на эту модель:

| Элемент | Механизм |
|---|---|
| BUFFER | `defineUnaryGate` (реализован) |
| MUX, DEMUX | число входов **и выходов** от свойства `selectBits` (реализованы, см. ниже) |
| CLOCK | `state` + `onTick`, свойство «Полупериод (тактов)» 1–16 (реализован) |
| D / T / JK FLIP-FLOP | фабрика `defineFlipFlop` + детектор фронта (реализованы, см. ниже) |
| D LATCH | `state`, управление уровнем (реализована) |
| HALF ADDER, FULL ADDER | несколько выходов |
| SR LATCH | `state`; решить поведение при S = R = 1 |

**Последовательные элементы** (`core/elements/sequential/`, категория `sequential`, палитра
«Триггеры и память»; CLOCK — `io/clock.ts`, группа «Ввод и вывод»):

- **Детектор фронта** (`edge.ts`): состояние хранит прошлый уровень такта `clk`; `null` — такт
  ещё не наблюдался (включение, новый элемент), первое вычисление только запоминает уровень.
  `clockEdge(prev, cur)`: `none` — такт не наблюдался, CLK = 0 или 1 → 1; `rising` — 0 → 1;
  иначе `possible` (X сейчас или раньше). Новое Q: `none` — хранение, `rising` — `next`,
  `possible` — `join(Q, next)`. X при `prev = null` не запоминается (иначе нарушится идемпотентность).
- **Только передний фронт**; асинхронных PRE / CLR, входа разрешения и заднего фронта нет
  (задний фронт — через NOT на такте).
- **`defineFlipFlop`** (`flipFlop.ts`): входы (включая `CLOCK_PIN` с `clock: true`), выходы Q, Q̄
  (`q`, `qn`), `initialState` Q = 0 и такт не наблюдался, `unknownState` Q = X; отличается только
  `next(data, q)`:
  - D: `next = D`; T: `next = T ⊕ Q`;
  - JK (`jkNext`): J = K = 1 — переключение, J — установка, K — сброс; значение **точное
    троичное** (J = 1, K = 0 устанавливает 1 и при Q = X — формула J·Q̄ + K̄·Q дала бы X).
- **D LATCH** (`dLatch.ts`): E = 1 — Q = D, E = 0 — хранит, E = X — `join(Q, D)`.
- Пины по роли: `d`, `t`, `j`, `k`, `e`, `clk` → `q`, `qn`; порядок входов у JK — J, CLK, K.
- **CLOCK**: выход `out0`, состояние `{ level, phase }`, уровень меняется каждые `halfPeriod`
  шагов, начальный уровень 0. По клику не переключается — время двигают Start / Step.

**MUX и DEMUX** (`core/elements/combinational/`) — отдельные определения с общим модулем
`select.ts` (свойство, пины выбора, адрес):

- свойство `selectBits` «Входы выбора», целое 1–3, по умолчанию 1: каналов 2^selectBits
  (MUX 2:1 / 4:1 / 8:1, DEMUX 1:2 / 1:4 / 1:8). Смена разрядности меняет набор пинов —
  структурное изменение: перекомпиляция, шаг истории, провода исчезнувших пинов удаляются;
- пины: MUX — входы `d0…d(n−1)`, `s0…s(k−1)` (`side: 'bottom'`), выход `y`; DEMUX — вход `d`,
  `s0…`, выходы `y0…y(n−1)`. **`s0` — младший разряд адреса.** Id по роли, поэтому при смене
  разрядности провода на сохранившиеся пины остаются (`in2` у индексных id стал бы другим пином);
- адрес (`readAddress`) — маска известных разрядов и их значения; `channelMatch` даёт для канала
  1 (выбран), 0 (исключён известным разрядом) или X (возможен при X в адресе);
- **X у MUX — точная семантика:** выход — общее значение всех каналов, которые адрес не исключает,
  иначе X. При S0 = X и D0 = D1 = 1 выход 1 (схема на вентилях в логике Клини дала бы X);
- **X у DEMUX:** выход канала = AND(D, совпадение) — выбранный получает D, исключённый — 0
  (даже при D = X), возможный — 0 при D = 0, иначе X. Тоже точное троичное расширение;
- неподключённый вход выбора = 0 (выбран канал 0).

Требования к `evaluate`:

- **детерминированность**;
- **монотонность по X**: если заменить вход на X, выход может стать только X, но не сменить 0 на 1;
- **идемпотентность**: повторное вычисление с теми же входами и возвращённым состоянием
  даёт те же выходы. Например, у триггера при X на CLK фронт считается возможным
  в любом случае, кроме CLK = 0;
- **число выходов совпадает с `pins().outputs`**.

Контрактные тесты (`tests/core/elements/contract.test.ts`) автоматически проверяют эти
требования для всех элементов реестра:

- перебираются **все** значения каждого целого свойства (вентили 2–8 входов, MUX до 8:1 —
  11 входов) и все троичные наборы входов;
- состояния — **полное замыкание** из `initialState` и `unknownState` по вычислениям на всех
  наборах входов и тикам (у триггера Q = 1 достигается только за два вычисления);
- `unknownState` проверяется отдельно: его выходы уточняются выходами любого достижимого состояния;
- монотонность проверяется заменой **одного** входа на X (3ⁿ·n вычислений): любой более грубый
  набор получается цепочкой одиночных замен, а отношение «X или то же значение» транзитивно.
  Для наборов до 4 входов дополнительно перебираются все пары (9ⁿ). Сама проверка покрыта
  мета-тестом: нарушение, проявляющееся только при двух X, обнаруживается;
- `expect` вызывается только при расхождении — на сотнях тысяч наборов сам вызов дороже
  вычисления (файл выполняется ≈ 1,2–1,4 с).

Id пинов задаются определением элемента и стабильны: у вентилей `in0..inN` и `out0`,
у сложных элементов — по роли (`d0`, `s0`, `y`, `y0`, `clk`, `q`, `qn`).

В редакторе символы задаются реестрами SVG-символов по `type`: `GATE_SYMBOLS` (вентили,
вид узла `gate`) и `MUX_SYMBOLS` (трапеции, вид узла `mux`); INPUT, OUTPUT и CLOCK — виды
`input`, `output`, `clock`. Для элемента без собственного символа используется универсальный
прямоугольный символ с названием и подписями пинов, поэтому новый элемент работает без
изменений в редакторе.

- **Прямоугольный символ** (`box`, триггеры и защёлка): сверху полоса названия
  (`BOX_TITLE_ROWS = 1` шаг сетки), пины боковых сторон начинаются под ней: «JK FLIP-FLOP»
  шире промежутка между подписями пинов. Высота `(рядов + 2) · 20`: D/T-триггер и D LATCH — 80,
  JK — 100. Тактовый вход (`PinSpec.clock`) отмечается значком ▷ сразу за кружком пина.
  В палитре — уменьшенный корпус с линиями пинов и ▷ (`features/palette/BoxPreview.tsx`).
- **CLOCK** (`nodes/ClockNode.tsx`): узел размером с INPUT — меандр и текущий уровень,
  атрибут `data-value`; по клику не переключается.

- **Геометрия `mux`** (`layout/geometry.ts`): входы слева, входы с `side: 'bottom'` снизу,
  выходы справа; пины каждой стороны центрируются с шагом сетки — на длинной стороне они
  идут от одного шага до края, одиночный пин (Y у MUX, D у DEMUX) встаёт посередине.
  Ширина 80, высота (каналов + 1) · 20: 60 / 100 / 180.
- **Трапеция** (`symbols/muxShapes.ts`, `MuxSymbol.tsx`): MUX сужается к выходу, DEMUX —
  к входу; наклон узкой стороны `min(20, h/4)`; линии входов выбора идут от нижнего края узла
  до наклонной стороны. Внутри — название, конфигурация («4:1», `muxRatio` по числу пинов)
  и подписи пинов. Корпус нейтральный, сигналы показывают пины.

### Соединения

- Провод всегда направлен от **выхода** к **входу**. При соединении в обратную сторону
  направление нормализуется (`resolveConnection`).
- У каждого входа не больше одного источника. Новый провод на занятый вход заменяет старый.
- Один выход может питать любое число входов.
- Запрещены соединения выход→выход и вход→вход, а также дубликаты.
  Соединение выхода элемента с его же входом разрешено (обратная связь).
- Сеть = выходной пин (`netId = componentId:pinId`).
- При удалении элемента или уменьшении числа входов удаляются связанные провода.
- **Неподключённый вход = логический 0**, но в интерфейсе он визуально выделяется
  (полый пин). В netlist такой вход имеет `inputNets[i] === null`.

### Симуляция

- `Signal = 0 | 1 | 'X'`, где `X` означает неопределённое значение. Для X используется логика
  Клини: `AND(0, X) = 0`, `AND(1, X) = X`, `NOT(X) = X`, `XOR(·, X) = X`.
- **Включение** (создание движка, reset): все сети 0, состояния — `initialState`, а **выходы
  элементов с состоянием сразу вычисляются из начального состояния** (Q̄ = 1 до первого расчёта).
  Иначе переход Q̄ 0 → 1 при включении выглядел бы фронтом для триггера, тактируемого от Q̄.
  То же для элемента, добавленного при перекомпиляции (его состояния нет в снимке `exportState`):
  триггер, появившийся вместе с проводами при высоком такте (вставка, Undo удаления), не срабатывает.
- **Компиляция** (`compileCircuit`) заменяет строковые id индексами, строит список читателей
  каждой сети, ранги (топологический порядок, обратные связи разрываются по DFS) и
  множество элементов в петлях (сильно связные компоненты).
- **Расчёт** (`engine.settle()`) — событийная релаксация без задержек. Элементы берутся
  из очереди по рангу и вычисляются с текущими значениями. Если выход изменился, в очередь
  ставятся читатели сети. Для схем без петель каждый элемент вычисляется не больше одного раза.
  - **Комбинационные элементы** (без `initialState`) обновляют выходы сразу (по Гауссу — Зейделю).
  - **Элементы с состоянием — дельта-циклы.** Состояние обновляется сразу, а выходы откладываются
    до момента, когда очередь опустеет; затем они публикуются, и начинается следующий цикл.
    Поэтому все триггеры одного фронта захватывают данные **до фронта**: сдвиговый регистр
    сдвигает на один разряд, счётчик Джонсона идёт 10 → 11 → 01 → 00, и результат не зависит
    от порядка элементов и проводов. Без этого (до этапа 9) значение проскакивало через весь
    регистр за один такт. Перекос такта через вентили (BUFFER на такте) обрабатывается верно.
  - **Подключение провода** с уровнем 1 к неподключённому тактовому входу (= 0) — настоящий
    переход 0 → 1: триггер срабатывает (как в железе).
  - **Одновременная смена D и CLK** (строка таблицы истинности) — триггер видит новое D.
    D, вычисляемое из того же такта через вентили, — гонка, результат зависит от рангов.
- **Устойчивые петли** (RS-защёлки на NOR и NAND, D-защёлки на вентилях) сходятся
  к неподвижной точке и хранят состояние в значениях сетей.
- **Ограничение модели без задержек.** Гонки и статические риски (глитчи) не моделируются.
  Пример — D-защёлка на мультиплексоре, собранном из вентилей, без согласующего терма D·Q.
  Для таких схем результат детерминирован (зависит от рангов), но может отличаться от реального
  железа. Элемент MUX вычисляется целиком, поэтому защёлка на нём (Y → D0, D → D1, E → S0)
  этой гонки не имеет.
  Показать такие эффекты сможет будущий режим с единичной задержкой.
- **Нестабильные петли.** Порог колебаний задаётся для каждого элемента отдельно
  (`oscillationThreshold`, по умолчанию 64 вычисления за один `settle()`), а не для схемы
  целиком.
  - Элемент, превысивший порог, помечается колеблющимся: до конца расчёта его выходы
    обновляются через `join(текущий, вычисленный)` (могут только перейти в X), а состояние
    заморожено.
  - Колебание гаснет в X, а остальная схема продолжает обычную релаксацию. Генератор не
    отнимает вычисления у независимых защёлок, поэтому защёлка, которая переключается
    в том же расчёте (включение, reset), получает определённое значение.
  - После релаксации проход уточнения заменяет X вычисленными значениями, где они однозначны.

  Расчёт конечен при любых `evaluate`:
  - непомеченный элемент вычисляется не больше порога раз (отложенная публикация следует
    за вычислением, поэтому тоже ограничена);
  - помеченный — меняет выходы не больше одного раза (в X, сразу, без откладывания);
  - при уточнении каждая сеть меняется не больше одного раза (из X).
- Результат `settle()`: `{ status: 'stable' | 'oscillation', evaluations, unknownNets }`.
  Интерфейс показывает предупреждение, если `unknownNets` не пуст.
- **Таблица истинности** (`core/analysis/truthTable.ts`) строится на реальном движке, без
  собственной логики:
  - входы и выходы — элементы с ролью `port`; порядок столбцов — по подписи (естественный:
    X2 раньше X10), затем элементы без подписи; при равенстве — по Y, X и id;
  - строки — двоичный счёт, первый вход — старший разряд; не больше
    `MAX_TRUTH_TABLE_INPUTS = 10` входов (1024 строки), иначе отказ `too-many-inputs`;
    без входов — одна строка; без выходов — отказ `no-outputs`; пустая схема — `empty`;
  - схема компилируется один раз; каждая строка считается в **отдельном экземпляре**
    `SimulationEngine`. Основной движок, хранилища и схема не затрагиваются;
  - **основной расчёт — от состояния «все сети X»** (`EngineOptions.initialState`): содержимое
    памяти неизвестно. Комбинационная часть и однозначно установленные петли получают 0 или 1,
    а значение, зависящее от предыдущего состояния, остаётся X. Если у выхода X, выполняется
    второй расчёт от состояния включения: X и там — ячейка `unknown` (колебание), иначе —
    `memory` («↺», хранит прошлое значение; значение после сброса — справка). Так RS-защёлка
    получает классическую таблицу, а не случайное значение после включения;
  - оценка консервативна: внутри петель трёхзначная логика может показать «↺» там, где
    значение на деле определено;
  - элементы с `unknownState` (триггеры, D LATCH) в основном расчёте начинают из него (Q = X):
    у D/T/JK-триггера Q во всех строках «↺» (зависит от прошлого), у D LATCH при E = 1 Q = D,
    при E = 0 — «↺»; комбинационная часть после триггера определена, где не зависит от Q.
    Элементы с состоянием без `unknownState` считаются от `initialState` (предупреждение
    `stateful-elements`); элементы времени (`onTick`, CLOCK) — при t = 0, без тактов (`time-elements`);
  - предупреждения: `memory`, `unknown`, `stateful-elements`, `time-elements`,
    `floating-inputs`, `duplicate-labels`, `diagnostics`.

### Состояние (store/)

- **Хранилища — vanilla-сторы Zustand** (`zustand/vanilla`), создаются фабриками
  (`createAppStores`). Тесты создают собственный экземпляр. React-хуки
  (`useCircuitStore`, `useSimulationStore`, `useUiStore` в `store/hooks.ts`) — тонкая
  обёртка над единственным экземпляром приложения.
- **`circuitStore`** хранит доменную `Circuit`: это единственный источник истины. Узлы
  React Flow строятся из неё адаптером в `editor/adapters/`. Изменения выполняются чистыми
  функциями `core/circuit/`.
  - **Документ.** Кроме схемы стор хранит название `name` (`renameDocument`), а также
    `savedCircuit` и `savedName` — состояние на момент последнего сохранения или загрузки
    (`markSaved`). Название сохраняется в файл, но не в историю undo/redo.
  - **`loadCircuit(circuit, { name, saved })`** — новый документ: история очищается,
    `saved: false` (схема исправлена при загрузке) оставляет индикатор несохранённых
    изменений включённым. `clear()` — новый пустой документ без названия.
  - **Индикатор несохранённых изменений** — селектор `selectIsDirty`: название отличается
    от сохранённого или `!circuitsEqual(circuit, savedCircuit)`. `circuitsEqual` сначала
    сравнивает ссылки (undo до сохранённого снимка возвращает тот же объект), затем
    содержимое — переключение INPUT туда и обратно или возврат элемента на место правкой
    не считаются.

  Влияние изменения определяет `classifyChange`:
  - `documentVersion` — загрузка или очистка: новый движок с состояния включения;
  - `structureVersion` — элементы, провода, порядок или набор пинов: перекомпиляция
    с `exportState()`;
  - `propsVersion` — свойства без смены пинов: `engine.setProps()` и инкрементальный пересчёт;
  - перемещение и подписи не меняют версий.
- **`simulationStore`** хранит состояние симуляции и изменяется только через свои действия:
  - результаты — сигналы всех пинов (ключ `componentId:pinId`), статус, `unknownNets`,
    неподключённые входы, элементы в петлях, диагностику, время, `hasTimeElements`.
    Их публикует мост (`simulationBridge.ts`) действием `publish`;
  - состояние запуска — `running` и `frequency`. Ими управляет контроллер
    (`simulationController.ts`) действиями `setRunning` и `setFrequency`.
- **`simulationController`** отвечает за Start, Pause, Step, Reset, частоту и таймер.
  - Одновременно активен не больше одного таймера.
  - Таймер останавливается при Pause, Reset, структурном изменении или загрузке схемы
    (`structureVersion`, `documentVersion`), исчезновении элементов времени и `dispose`.
  - Start и Pause доступны, только если в схеме есть элементы с `onTick`
    (`hasTimeElements`). Reset доступен всегда.
- **`uiStore`** хранит выделение, панели, тему, открытый диалог, режим размещения тапом,
  буфер обмена, очередь уведомлений и `pendingDocument` — документ, ожидающий
  подтверждения в диалоге `discard-changes`.
  - Выделение очищается от исчезнувших элементов при структурных изменениях.
  - Очередь уведомлений ограничена. Повтор того же сообщения не добавляет новое,
    а обновляет существующее. Тоны: `info`, `warning`, `error`; уведомление `error`
    не скрывается само.
  - `closeDialog()` сбрасывает и `pendingDocument`: Esc в диалоге подтверждения отменяет действие.
- **`updateManyProps`** меняет свойства нескольких элементов одним изменением схемы: один
  `propsVersion`, один пересчёт в мосте, без промежуточных состояний защёлок. В историю не
  пишется, если меняются только интерактивные свойства.
- **История undo/redo** хранит неизменяемые снимки `Circuit` (до 100 шагов).
  - Перетаскивание и другие серии изменений объединяются через `beginBatch()` и `endBatch()`.
  - Изменения свойств из `interactiveProps` (положение INPUT) не записываются в историю.
    При undo/redo их текущие значения сохраняются (`carryInteractiveProps`).
- **Действия, затрагивающие несколько хранилищ**, — в `store/commands.ts`. UI вызывает их,
  а не сторы по отдельности. Это удаление выделенного, размещение, переключение INPUT,
  копирование, вырезание, вставка, дублирование, «выделить всё», очистка, перемещение
  выделенного стрелками, а также команды документа:
  - `newDocument()` и `openDocument(fileName, text)` — при несохранённых изменениях документ
    откладывается в `pendingDocument` и открывается диалог; `confirmPendingDocument()`
    и `cancelPendingDocument()` завершают его;
  - при замене документа выделение, режим размещения и счётчик вставок сбрасываются явно
    (id нового документа могут совпасть со старыми), буфер обмена сохраняется;
  - `saveDocument(download, fallbackName)` сериализует документ и вызывает `download`;
    `markSaved()` выполняется, только если `download` не выбросил исключение;
  - команды возвращают результат с кодами ошибок и предупреждений; тексты уведомлений
    формирует интерфейс (`features/file/fileMessages.ts`), сторы не зависят от `i18n`;
  - `applyInputCombination(values)` — строка таблицы истинности: все INPUT получают
    комбинацию через `updateManyProps` (без истории, один пересчёт).

### Редактор (editor/)

- **React Flow — только визуальный слой.** Второй модели схемы нет.
  - Узлы и рёбра строятся из `circuitStore` адаптером `adapters/flowMapping.ts`.
  - Кэш `FlowCache` переиспользует объекты неизменённых элементов.
  - Выделение хранится в `uiStore`.
  - Изменения React Flow (`NodeChange`, `EdgeChange`) переводятся в действия хранилищ
    функциями `adapters/flowChanges.ts`.
- **Размеры узлов и точки подключения задаются явно** из детерминированной геометрии
  (`layout/geometry.ts`) через поля `width`, `height`, `measured` и `handles`. Без `measured`
  React Flow сбрасывает `handleBounds` и заново измеряет узел, и провода моргают.
- **Сигналы** узлы и провода читают из `simulationStore` селекторами (`hooks/useSignals.ts`).
  Изменение сигнала не пересоздаёт узлы React Flow. Цвета берутся только из `signalStyle.ts`.
- **Соединения:**
  - режим `ConnectionMode.Loose`;
  - допустимость проверяет `canConnect` — то же правило ядра (`resolveConnection`), что
    в хранилище;
  - концы проводов переподключаются (`circuitStore.reconnect`), а бросок конца на пустое место
    удаляет провод.
- **Перетаскивание** объединяется в один шаг истории (`beginBatch` и `endBatch`)
  и не перекомпилирует netlist.
- **Клавиши** обрабатывает `hooks/useKeyboardShortcuts.ts` по `event.code`, поэтому они
  работают в русской раскладке. Встроенное удаление React Flow отключено
  (`deleteKeyCode={null}`). Модель клавиш (`shortcuts.ts`) общая; файловые действия
  (`isFileShortcut`: Ctrl+S, Ctrl+O) редактор пропускает — их выполняет
  `features/file/useFileShortcuts.ts`, в том числе в полях ввода.
- **Контекстное меню** строится моделью `contextMenuModel.ts`. Свойства элемента (например,
  число входов) берутся из `propSchema`, без проверок по типу.
- **Автоподписи** INPUT (X1, X2, …) и OUTPUT (Y1, …) задаются полем `labelPrefix`
  в определении элемента.
- **Начальный вид поля фиксирован** (`DEFAULT_VIEWPORT`). Свойство `fitView` у React Flow
  не используется: иначе поле «прыгает» при добавлении первого элемента.
  При смене документа (`documentVersion`: открытие файла, новая схема)
  `hooks/useFitViewOnLoad.ts` вписывает схему в экран, а пустую показывает в начальном виде.
  Обычные правки вид не меняют.
- **Клавиатурные функции React Flow отключены** (`disableKeyboardA11y`). Стрелки двигают
  выделенное через `commands.nudgeSelection`, без двойного перемещения.
- **Инспектор** (`features/inspector/`) строится чистой моделью `inspectorModel.ts`:
  выделение + схема + реестр → модель отображения. Редактор свойства (`PropField`) общий
  для инспектора и контекстного меню. Инспектор не меняет положение и масштаб поля;
  «показать элемент» сдвигает вид, сохраняя масштаб.
- **Имена файлов.** Файловая система Windows не различает регистр. Не создавать файлы,
  имена которых отличаются только регистром (`ContextMenu.tsx` и `contextMenu.ts`),
  иначе импорты разрешаются в чужой файл.

### Пошаговая симуляция (архитектура)

- Распространение сигналов всегда мгновенное (`settle`, с дельта-циклами для элементов
  с состоянием). Время двигают только элементы с `onTick` — CLOCK. Кнопки Start / Pause / Step
  и частота появляются, когда в схеме есть CLOCK; Reset доступен всегда.
- Повторный Start продолжает с текущего состояния — искусственных фронтов нет; Reset
  возвращает время 0, CLOCK — уровень 0, триггеры — Q = 0, Q̄ = 1.
- `engine.tick()` увеличивает `time`, вызывает `onTick` у элементов, затем `settle()`.
- Мост (`appStores.simulationBridge`) выполняет `step()` и `reset()` над движком.
  Интерфейс управляет симуляцией только через контроллер
  (`appStores.simulationController`):
  - **Start** — периодический `step()` с частотой `frequency` (тиков в секунду);
  - **Pause** — остановка таймера;
  - **Step** — один шаг;
  - **Reset** — остановка и возврат к состоянию включения.

  Переключение `INPUT` на паузе пересчитывается сразу.
- Возможное расширение — режим с единичной задержкой вентиля (пошаговая визуализация
  распространения). Очередь событий движка это допускает.

### Формат файла

- **Файл** — JSON с полями `format: "logic-sim"`, `version` (сейчас `1`), `name`,
  `components` (`id`, `type`, `position {x, y}`, `label?`, `props`) и `wires`
  (`id`, `from`, `to` — `{ componentId, pinId }`). Служебные поля React Flow и состояние
  симуляции в файл не попадают: после загрузки симуляция начинается с состояния включения.
- **Расширение** — `.lsim`; при открытии принимаются `.lsim` и `.json`. Размер — до 5 МБ.
- **Сериализация** (`serializeCircuit`) детерминирована: поля перечислены явно, ключи
  `props` отсортированы, отступ 2. Сохранение → загрузка даёт ту же схему.
- **Разбор** (`parseCircuitFile`) — чистая функция. Стадии: размер → JSON → `format` →
  версия и миграции → структура и уникальность id → типы по реестру → нормализация.
  Схема загружается только целиком: при критической ошибке текущий документ, история,
  название и симуляция не меняются.
- **Критические ошибки** — файл отклоняется: неверный JSON, чужой `format`, неверная или
  более новая версия, нет обязательного поля или неверный тип, неверная структура элемента
  или провода, повтор id элементов или проводов, неизвестный тип элемента.
- **Исправимые ошибки** — схема нормализуется существующими операциями ядра
  (`insertFragment` → `addComponent` с `resolveProps` и `pruneInvalidWires`) и загружается
  с предупреждением: свойства исправлены (значения по умолчанию, типы, диапазон, лишние
  ключи), удалены подписи неверного типа, удалены провода, нарушающие правила соединений.
- **Ошибки и предупреждения** ядро возвращает кодами (`FileError`, `FileWarning`);
  тексты лежат в `i18n/ru.ts` (`ru.file.errors`, `ru.file.warnings`).
- **Миграции** (`migrations.ts`): `MIGRATIONS[N]` переводит версию N в N + 1. При изменении
  формата повышается `CURRENT_VERSION` и добавляется миграция с тестом.

### Интерфейс и UX

- **Язык.** Интерфейс полностью на русском, все строки лежат в `src/i18n/`. Названия
  элементов международные: AND, OR, XOR, MUX и т.д.
- **Символы.** Вентили изображаются по стандарту ANSI (IEEE Std 91), корректными SVG-символами:
  - инверсия — кружок на выходе;
  - BUFFER — треугольник без кружка (как NOT, но без инверсии);
  - XOR и XNOR — двойная входная дуга;
  - OR, NOR, XOR и XNOR — вогнутая входная сторона;
  - MUX и DEMUX — трапеция (общепринятое изображение; строго по IEEE Std 91 это прямоугольник
    с пометкой MUX), входы выбора снизу. В палитре — группа «Комбинационные схемы»;
  - триггеры и D LATCH — прямоугольник с названием сверху, выходы Q и Q̄, у тактового входа
    значок динамического входа ▷ (IEEE Std 91). В палитре — группа «Триггеры и память»;
  - CLOCK — узел с меандром и текущим уровнем, в группе «Ввод и вывод».
- **Соединения:**
  - у пинов увеличенная невидимая зона захвата, а при отпускании провод притягивается
    к ближайшему пину (`connectionRadius`);
  - во время протягивания подходящие пины подсвечиваются, неподходящие приглушаются;
  - провод можно тянуть и от входа, и от выхода;
  - концы провода можно переподключить перетаскиванием;
  - провод выделяется кликом и удаляется клавишей Delete.
- **Навигация:** панорамирование перетаскиванием пустого поля, зум колесом и щипком,
  «вписать в экран», мини-карта, привязка к сетке.
- **Сигналы:**
  - пины и провода окрашиваются по значению: 1 — ярким цветом, 0 — нейтральным серым,
    X — предупреждающим цветом с пунктиром;
  - неподключённые входы показываются полыми;
  - OUTPUT светится при 1, INPUT показывает 0/1 и переключается кликом;
  - при наличии X выводится предупреждение.
- **Адаптивность:** на узких экранах палитра и инспектор становятся выдвижными панелями.
  Рабочая область между тулбаром и строкой состояния (`data-testid="workspace"`) имеет
  `overflow-hidden`: закрытые панели сдвинуты за край и не расширяют страницу.
- **Сенсорный ввод.** На устройствах с грубым указателем (`pointer: coarse`) тап по элементу
  палитры включает режим размещения (`uiStore.placement`), а следующий тап по полю ставит
  элемент. С мышью клик по палитре добавляет элемент в центр поля.
- **Уведомления** коротко объясняют, почему соединение не создано, и сообщают о замене
  провода на занятом входе.
- **Справка** по горячим клавишам открывается по F1 или «?».
- **Файлы** (`features/file/`):
  - кнопки «Новая», «Открыть», «Сохранить» в тулбаре; точка на «Сохранить» — есть
    несохранённые изменения; название схемы — поле в тулбаре и в разделе «Документ» инспектора;
  - Ctrl+S — сохранить (скачивание через Blob), Ctrl+O — открыть (`<input type="file">`);
  - перед заменой изменённого документа — диалог подтверждения («Отмена» / «Не сохранять»);
  - при закрытии вкладки с несохранёнными изменениями браузер спрашивает подтверждение
    (`beforeunload`); заголовок вкладки — «● Название — Логический симулятор»;
  - на узком экране логотип и «Новая» скрыты в тулбаре; «Новая» и название доступны
    в разделе «Документ» инспектора.
- **Таблица истинности** (`features/truthTable/`):
  - открывается кнопкой тулбара (на узком экране скрыта), кнопкой в разделе «Схема»
    инспектора и пунктом контекстного меню поля; для пустой схемы недоступна;
  - модальный диалог `Dialog` с `size="wide"`; таблица строится один раз при открытии
    (схема не меняется, пока диалог открыт); модель отображения — `truthTableModel.ts`;
  - сводка, предупреждения, закреплённая шапка «Входы / Выходы», легенда; 0, 1 и X — цвета
    сигналов из `signalStyle.ts`, «↺» — отдельный цвет и пояснение, что это не сигнал;
  - одинаковые заголовки столбцов получают номер: «X1 (1)», «X1 (2)»;
  - строка текущей комбинации INPUT подсвечена; клик или Enter по строке применяет
    комбинацию к схеме (`applyInputCombination`), диалог остаётся открытым;
  - на узком экране таблица прокручивается внутри диалога по обеим осям.

## 4. Правила разработки

- Не объединять всю логику в одном файле. Один модуль — одна ответственность.
- Не дублировать код: общую логику выносить в `core/`, `lib/` или `components/ui/`.
- Писать только на TypeScript в режиме `strict`. Не использовать `any` без веской причины.
- Logic Engine (`core/`) отделён от интерфейса и не зависит от React.
- Использовать переиспользуемые компоненты. Новый UI сначала ищет подходящий компонент
  в `components/ui/`.
- Не удалять и не ломать работающую функциональность при добавлении новых возможностей.
  Если изменение затрагивает существующее поведение, явно сообщить об этом.
- Не использовать готовые платные шаблоны.
- Интерфейс должен быть современным, удобным и адаптивным.

## 5. Тестирование

Перед завершением каждого этапа:

1. **TypeScript:** `npm run typecheck` — без ошибок.
2. **Сборка:** `npm run build` — успешна.
3. **Линтер:** `npm run lint` — без ошибок.
4. **Логические функции:** `npm test` — unit-тесты всех элементов, включая значения X.
5. **Соединения и симуляция.** Должны быть тесты:
   - правил соединений: направление, единственный источник у входа, замена провода,
     удаление связанных проводов;
   - движка: комбинационные схемы (полусумматор, сумматор); устойчивые петли
     (RS-защёлки на NOR и NAND, D-защёлка); нестабильные петли (NOT на себя,
     кольцо из нечётного числа инверторов → X); инвариант неподвижной точки после
     `settle()` на случайных схемах;
   - таблиц истинности и сериализации (сохранение → загрузка даёт ту же схему);
   - последовательной логики (`engine.sequential.test.ts`, на `TEST_DFF` и `D_FLIP_FLOP`):
     сдвиговый регистр, счётчик Джонсона, асинхронный и синхронный счётчики, перекос такта,
     отсутствие фантомных фронтов (включение, reset, добавленный триггер), независимость
     от порядка элементов, перенос состояния при перекомпиляции.
6. **Сценарии в браузере:** `npm run test:e2e` (Playwright, Chromium, production-сборка через
   `vite preview`). Сценарии лежат в `e2e/` и проверяют работу с мышью и клавиатурой:
   перетаскивание, провода, выделение, горячие клавиши, контекстное меню, отображение
   сигналов, отсутствие перекомпиляции при перемещении (атрибут `data-compilations`
   строки состояния). Элементы интерфейса для сценариев помечаются `data-testid`.
   - Сенсорный ввод проверяется отдельными сценариями с эмуляцией телефона
     (`hasTouch`, `isMobile`, ширина 390 px), а не мышиными.
   - Вёрстку на узком экране проверять явно: видимость кнопок, отсутствие
     горизонтального переполнения.
   - В Tailwind v4 скрывать элементы с базовым `inline-flex` или `flex` через
     `max-sm:hidden`, а не через `hidden sm:inline-flex`: побеждает порядок правил в CSS.
   - Выдвижные панели анимируются. После открытия ждать `expectPanelOpen`, после закрытия —
     `expectPanelClosed` (`e2e/support.ts`), а не `toBeInViewport`: тап по полю, пока
     палитра уезжает, попадает в её кнопку.
   - Схемы для сценариев загружаются из `.lsim`: `circuitFile` и `openCircuit` в `e2e/support.ts`.
     `circuitFile` дополняет свойства значениями по умолчанию (`defaultProps` там же): новый тип
     со свойствами нужно добавить туда, иначе загрузка сообщит о нормализации.
     У OUTPUT и CLOCK значение — атрибут `data-value`, у вентилей — `data-output`, у любого
     пина — `data-signal`. Время — `sim-time` с текстом `t = N` (виден на широком экране).
   - Последовательные схемы проверять по шагам (`sim-step`); при Start с таймером сверять
     инвариант (значение счётчика = числу фронтов за `t` шагов), а не точное время.
     После загрузки поле вписывается в экран с анимацией — клики по полю делать в свободной
     области (например, в правом верхнем углу) или после ожидания узлов.
   - Файлы проверяются событиями `download` и `filechooser`. `download.path()` — временный
     файл без расширения: для повторного открытия передавать содержимое с именем
     `suggestedFilename()`.

Тесты для `core/` пишутся вместе с кодом, а не после него. Нельзя сообщать, что проверка
пройдена, если она не запускалась или упала.
